## 实现

- 注册 `grok-cli` 适配器，自动发现 PATH 或 `~/.grok/bin/grok`，运行时 ID 为 `runtime:grok-cli`。手动注册的运行时使用其指定的可执行文件。
- 直接运行原生非交互 CLI，复用现有登录；Relay 不读取登录 cookie/token，也不要求重复输入 API Key。
- 从 `grok models` 获取模型，再从同版本 CLI 的有界模型缓存中提取公开的名称、推理选项和默认强度。只补充当前目录列出的模型；缓存中的认证字段、身份、请求头和端点不会进入 Relay。
- 支持模型和推理选择、工作目录、结构化工具事件、继续原生会话、取消进程。CLI 签名用量数据不落入 Relay 事件日志。文本按回复合并，避免控制台出现逐字碎片。
- 任务和指令放入临时私有文件，结束或启动失败后清理。创建会话时预分配 UUID，因此无需等待末尾的 `sessionId` 即可取消。
- 只读/建议模式使用 `read-only` 沙箱及 `dontAsk`；写入模式使用 `workspace` 沙箱及 `bypassPermissions`，仍遵守 Grok 的 deny 规则及管理策略。只声明工作区写入边界，不声明命令或网络隔离。运行中发送消息和子 Agent 不提供。
- macOS 下，未设置任何 HTTP/HTTPS/ALL_PROXY 环境覆盖（含小写及空值覆盖）时，从系统设置提取已启用的静态代理，仅传给 Grok 子进程。自动更新也仅在该子进程中关闭。
- 子进程合并已有的 `NO_PROXY` / `no_proxy`，强制排除 localhost、IPv4/IPv6 回环地址；Relay 主进程的环境不变。本地桌面端、MCP、守护进程探测的 HTTP 客户端始终直连，Relay 的 GitHub 更新检查保留独立的系统/环境代理客户端。
